# AA 分摊功能 · 第二轮联调测试计划（客户端 UI 专项）

> 本文档基于 `aa-settlement-final-plan.md`（最终落地实施方案）制定，是对第一轮联调测试的**查漏补缺与系统性覆盖**。
> 本轮新增客户端 UI 实现，**测试重点完全转移到客户端（Flutter App）**：覆盖所有 UI 元素渲染、交互逻辑、数据绑定、状态切换及用户操作路径的完整性。
> **明确排除项：Web 端任何测试内容不在本轮范围。** 服务端仅作为联调数据源验证（同步回读），不做接口测试。

---

## 1. 测试目标

1. 验证客户端 AA 分摊全链路 UI 元素渲染正确、可交互、无崩溃。
2. 验证数据绑定（Provider → 页面 → 控件）正确，写库 → 回读 → 跨页面刷新一致。
3. 验证状态切换（账本开关、分摊模式、参与人选择、虚拟用户管理、编辑/取消）符合模型 B' 落库时机约定。
4. 验证所有用户操作路径（新建/编辑/查看/结算/开关）完整闭环，无死路径、无状态丢失。
5. 系统性覆盖边界与异常流程，确保第一轮遗漏场景全部补测。

## 3. 前置条件与环境

| 项 | 要求 |

| 设备 | 真机 ≥1 台（Android/iOS 均需） + 模拟器 1 台（小屏验证） |
